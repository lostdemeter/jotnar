# Jotnar: a compiler for geometric assembly AI programs

Write AI programs once in geometric assembly — a small shader-like ISA
over typed streams — and compile them to **C** (portable reference),
**CUDA** (kernels + cuBLAS on the GPU), or **integer-only C** (bit-exact,
no FPU, no libm). A Python frontend (`chain.builder`) builds programs
without hand-writing listings. Every backend is gated against the others;
agreement is leveled: **bit-exact where integer, epsilon where float,
decisions where saturated**. Missing ops or backends fail loud
(`NoPattern`), never silently.

## Codec mode

`compile_program(..., mode="codec")` emits a small in-process codec ABI for
fully static F/I programs:

```c
JotnarCodec *jotnar_codec_create(void);
int jotnar_codec_bind(JotnarCodec *c, const char *name,
                      void *data, size_t bytes, int mode);
int jotnar_codec_step(JotnarCodec *c);
void jotnar_codec_destroy(JotnarCodec *c);
```

Bindings are frozen-read (`0`), live-read-write (`1`), or
output-write (`2`). `live=[...]` names the read-write bindings; all other
non-const inputs are read-only; intermediates are allocated once in
`create`. The contract is deliberately narrow — F/I only, fully static
shapes, no T/dynamic/graph/pack — so the ABI stays boring. Use
`build_shared` to compile it, or run `tests/test_codec_c.py` for the
one-shot parity and loud bind failures. This is the seed for host codecs;
the same lowering can be emitted for CUDA and non-FPU later.

## Demo 1: image pipeline (seconds, all three backends)

```
python3 demo_img.py
```

## Demo 2: chat (needs snapshot + one build)

```
python3 scripts/download_qwen7b.py   # pinned snapshot, cache-hit if present (~15 GB)
python3 scripts/smoke_qwen7b.py      # tokenizer + one weight, no GPU
# Build WITHOUT QWEN_REUSE_BIN (the key means reuse-only and refuses a fresh
# workdir); re-runs and gates may set it once build.json exists:
env -u QWEN_REUSE_BIN QWEN_WORKDIR=/tmp/dec7b512 \
  python3 scripts/serve_decode.py --smax 512 "hello"
python3 scripts/run_demo_chat.py                     # REPL, defaults below
```

The build compiles the 28-layer decode binary once into the workdir
(`qdec` + `build.json` stamp; reused on later runs). REPL defaults:
`--smax 512 --n 40 --workdir /tmp/dec7b512 --topk 12 --temp 0.8 --seed 7`,
commands `/quit /reset /seed /topk /temp`. Sampling is host-boundary;
listings stay deterministic (replay a session by re-entering lines).

Speed paths (same server; one workdir per config — the stamp refuses to mix
configs, so build each without `QWEN_REUSE_BIN`, then re-runs may set it):

```
env -u QWEN_REUSE_BIN QWEN_WORKDIR=/tmp/dec7b16 \
  python3 scripts/serve_decode.py --smax 16 "the capital of france is" --n 8
python3 scripts/serve_prefill.py "the capital of france is" --outdir /tmp/prefill
env -u QWEN_REUSE_BIN QWEN_WORKDIR=/tmp/dec7b_sp16 \
  python3 scripts/serve_decode.py --smax 16 --sparse-bands 4-11,21-27 --sparse-k 8
env -u QWEN_REUSE_BIN QWEN_WORKDIR=/tmp/dec7b_res16 \
  python3 scripts/serve_decode.py --smax 16 --resident-cache
```

KV-cache (files), sparse band-map readout, and on-device resident caches
are the three serving grades; gates `test_decode/test_prefill/test_sparse/
test_resident` pin each against HF and against each other.

Protocol loopback (see `docs/PROTOCOL.md`): the same server behind
messages — client builds listings, node executes blind:

```
python3 protocol/demo_paris.py --n 6   # needs snapshot + the Demo 2
                                       # smax-512 build above; Paris

python3 protocol/demo_paris.py --tcp --n 6
                                       # same answer over real TCP
                                       # sockets (reuses the Demo 2
                                       # build; --workdir isolates)
```

## Demo 3: pipelined Paris (needs snapshot + two stage builds)

```
python3 protocol/demo_paris.py --tcp --pipeline 0-13,14-27 --smax 16 --n 2
```

Shards the 28 decode layers across two socket nodes (0-13 / 14-27);
the controller ferries the f32 boundary, caches stay sticky per
stage. First run builds 2 stage binaries (minutes); warm runs are
seconds per turn. Workdirs live under `/tmp/pipe16` (never the Demo
2 build). Answer is text-identical to single-node (` Paris.`), and
the run ends with the hetero kicker: an integer chain placed on the
lattice node through the same controller. Gate:
`tests/test_protocol.py` pipe legs (per-layer KV, LOGITS, choice
bit-exact vs single-node).

Coverage: C 48, CUDA 37, non-FPU 43. Refusal cells are gated
(`test_emit.py` loud-refusal row). Full per-mnemonic contracts with
examples: `docs/LANGUAGE.md`. Extension recipe: registry row + shape
rule + one pattern per backend (`chain/backends.py`).

Shape-only inputs: `FRef`, `IRef`, and `TRef` (`chain.emit_c`) carry
shape/dtype without storage. Pass them in `sample` to compile multi-GB
weights or triple banks without allocating the payload; C and non-FPU
codegen only need the geometry. Values are still supplied at run time.
CUDA refuses T inputs at data-prep, so `TRef` is a C/non-FPU compile
stub (use FRef for the CUDA F path).

## Frozen, not generated

`chain/M.json` (integer scales) and `chain/CTRL.json` (controller fit) are
frozen doctrine: tracked, never regenerated on main. Their generators were
one-shot research scripts and retired with the `research` branch.

## Contracts

- Unknown mnemonics, arity mismatches, use-before-def, layout conflicts,
  shape mismatches: `AsmError` naming op and line (`tests/test_asm.py`).
- Serving grades decisions, not strings: sampling lives on the host
  boundary (`--topk/--temp/--seed`); listings are greedy-deterministic.
- This README was followed verbatim from a clean checkout before merge;
  every command above ran as written.
